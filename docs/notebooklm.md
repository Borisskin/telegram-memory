# Куки NotebookLM: вход и обновление

Секрет `notebooklm_cookies` — исходные куки аккаунта Google, который владелец использует только для сводок NotebookLM. Сервер `notebooklm-mcp` работает без браузера: вход выполняется на машине владельца, а состояние (`nlm`) с обновляемыми куки и CSRF-токеном хранится в томе `telegram_data` контейнера `telegram-mcp`. Точка входа контейнера копирует секрет в состояние при первом старте или когда хеш секрета отличается от последнего применённого. Поэтому пересоздание контейнера не затирает куки, обновлённые самим `nlm`.

## Формат секрета

Файл `cookies.json` профиля `notebooklm-mcp-cli`: JSON-объект «имя куки → значение» (принимается и список cookie-объектов). На сервере он лежит в `/etc/telegram-memory/secrets/telegram-mcp/notebooklm_cookies`; в репозиторий куки не попадают.

## Первый вход (на машине владельца, Windows)

1. Установить ту же версию клиента, что закреплена в образе (`config/vendors.json`, сейчас 0.15.5): `uv tool install notebooklm-mcp-cli==0.15.5` или `pip install notebooklm-mcp-cli==0.15.5`.
2. Выполнить `nlm login` — откроется браузер. Войти в аккаунт Google, предназначенный только для этой задачи, и дождаться `SUCCESS!`.
3. Файл куки — `%USERPROFILE%\.notebooklm-mcp-cli\profiles\default\cookies.json`. Передать его на сервер:

   ```powershell
   scp $env:USERPROFILE\.notebooklm-mcp-cli\profiles\default\cookies.json сервер:/tmp/cookies.json
   ssh -t сервер 'cd telegram-memory && sudo scripts/secrets-setup.sh --cookies /tmp/cookies.json'
   ```

Скрипт проверяет, что файл — корректный JSON, записывает куки и удаляет `/tmp/cookies.json`. До первой установки он только записывает файл; на установленной системе сам пересоздаёт `telegram-mcp`. Остальные секреты не меняются. Подробнее — в [развёртывании](deployment.md#замена-секретов-и-настроек).

## Обновление

Куки Google устаревают раз в несколько недель. Признак — оповещение Приёмщика, ошибка `notebook_auth` или ответ `expired` средства `refresh_auth`.

1. Повторить `nlm login` на машине владельца: свежие куки появятся в том же файле профиля.
2. Передать их теми же `scp` и `secrets-setup.sh --cookies`.

Хеш секрета изменился, поэтому точка входа контейнера скопирует его в состояние заново. Состояние в контейнере вручную трогать не нужно: сервер сам ротирует куки и обновляет CSRF внутри тома `telegram_data`.
