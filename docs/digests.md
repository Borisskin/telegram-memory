# Сводки

Сводка — краткий пересказ сообщений групп и каналов за период. Сообщения для сводки нигде не сохраняются и не отмечаются прочитанными. Сводки делает только Собеседник с правом на сводки — обычно «мой».

## Откуда берётся текст

- Группа или канал полного сбора — из архива.
- Остальные — из telegram-mcp средством `list_messages(chat_id, limit, from_date, to_date)`. Даты поставщика — дни UTC, координатор обрезает окно точно по времени. Если упёрлись в `limit`, сводка сообщает о неполноте.
- Личная область в сводки не попадает: такой запрос отклоняется с `forbidden_area` ещё до чтения.

## Длина периода

| Период | Кто пишет сводку |
|---|---|
| До 7 дней | Модель Собеседника через прокси. Координатор отдаёт сырой Markdown (`kind: raw`) |
| От 8 дней до 3 календарных месяцев включительно | NotebookLM во временном блокноте (`kind: summary`), токены своей модели не тратятся |
| Больше 3 месяцев | Ошибка `range_too_long` |

## По запросу

У Собеседника «мой»:

```
/digest <ссылка на группу или @имя> ГГГГ-ММ-ДД
/digest <ссылка на группу или @имя> ГГГГ-ММ-ДД..ГГГГ-ММ-ДД
```

Без аргументов бот покажет кнопками 10 последних активных групп (`list_chats` telegram-mcp), затем спросит даты. Ошибки формата объясняются без обращения к Telegram и модели.

## По расписанию

- Раз в день в одно время для всех групп в режиме «только сводка». По умолчанию 09:00 по часовому поясу владельца (сейчас закреплён `Europe/Moscow`); время меняется у Приёмщика командой `/digest_time HH:MM` и действует со следующего дня.
- Одно сообщение, в нём раздел на каждую группу; группы без новых сообщений пропускаются, пустая сводка не отправляется.
- Окно сводки — с конца предыдущей. Оно сдвигается только подтверждением `digest_commit` после успешной отправки, поэтому при сбое модели или Telegram пропущенное попадёт в следующую сводку.
- Если сбоит само подтверждение, повторяется только оно — сводка повторно не отправляется. После сбоя модели запросы к ней повторяются с нарастающим интервалом.
- Известное ограничение: если процесс упадёт ровно между отправкой и подтверждением, в тот же день сводка придёт второй раз. Это сознательный выбор «лучше дубль, чем потеря».

## NotebookLM

Длинная сводка проходит по шагам: создать блокнот → добавить Markdown → запросить сводку → удалить блокнот. Блокнот удаляется и при ошибке, сообщения хранятся в Google считаные минуты. При сбое NotebookLM сводка не перекладывается на модель прокси.

- Ошибка входа — `notebook_auth` и оповещение в Приёмщике «куки NotebookLM протухли», не чаще раза в сутки.
- Исчерпан лимит — `notebook_quota` с временем сброса.

NotebookLM работает через неофициальный API, поэтому возможны поломки без предупреждения; куки нужно обновлять раз в несколько недель. Как войти и обновить куки — в [отдельной инструкции](notebooklm.md).
