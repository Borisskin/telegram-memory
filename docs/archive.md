# Архив

Архив — единственный источник истины: Markdown с YAML-заголовком, UTF-8 без BOM, окончания строк LF. Файлы читаются любым Markdown-приложением, отдельных HTML и `metadata.json` нет. Пишет в архив только координатор.

## Раскладка

```
telegram/
  channels/<chat_id>/<message_id>.md          публикации каналов
  groups/<chat_id>/<message_id>.md            сообщения групп полного сбора
personal/<владелец>/
  notes/<штамп>_tg.md | <штамп>_web.md         свои тексты и веб-страницы
  forwards/<штамп>_fwd.md                     пересылки (from_user_id или sender_name)
  people/<user_id>/profile.md                 человек: имя, @username, прежние имена
  people/<user_id>/chat/<ГГГГ-ММ>/<message_id>.md   личная переписка
```

- `chat_id` — знаковый десятичный идентификатор Telegram. Название источника хранится в метаданных и на путь не влияет: после переименования каталог тот же.
- Штамп в имени личной записи — `ГГГГ-ММ-ДД_ччммсс` момента первого приёма по часовому поясу `Europe/Moscow`; полное время UTC — в заголовке. Совпадающие имена получают суффиксы `_01`…`_99`, сотое совпадение за секунду — ошибка `name_exhausted`.
- Пример имени: `notes/2026-09-21_143507_web.md`. Одна и та же страница (по нормализованному запрошенному адресу) остаётся в одном файле, изменения становятся её редакциями.
- Вложения лежат в `attachments/` отдельными файлами с именем по SHA-256 и безопасным расширением.
- Из каналов, групп и личных переписок скачиваются только фото и только у источника, где владелец включил «скачивать картинки». Остальные вложения остаются пометкой в `attachments` без файла. Файлы, которые владелец прислал Приёмщику, сохраняются, если OpenViking поддерживает их формат.

## Метаданные

Основные поля заголовка:

| Поля | Назначение |
|---|---|
| `schema_version`, `archive_id`, `revision` | Версия формата (`1`), устойчивый ключ записи, номер редакции |
| `source_kind`, `source_id`, `source_name` | Вид: `telegram_channel`, `telegram_group`, `personal_chat`, `person_profile`, `personal_telegram`, `personal_web` |
| `chat_id`, `message_id`, `owner_id` | Идентификаторы Telegram и владельца, десятичными строками |
| `from_user_id`, `sender_name`, `person_id` | Отправитель пересылки и человек личной переписки |
| `published_at`, `edited_at`, `received_at`, `observed_at`, `retrieved_at` | Даты ISO 8601 UTC; дата получения не подменяет неизвестную дату публикации |
| `source_url`, `requested_url`, `final_url` | Ссылка на источник; для веб-страницы все три обязательны |
| `status`, `availability`, `deletion_evidence` | `active` или `deleted`; доступность; свидетельство удаления |
| `content_hash`, `previous_revision`, `previous_content_hash` | Хеш значимого содержания и связь с предыдущей редакцией |
| `attachments` | Тип, имя, размер, путь, SHA-256 и состояние каждого вложения: `ready` — файл в архиве, `skipped` — не скачивался по правилам, `unavailable` — скачать не удалось, `unsupported` — формат не принимается |

Неизвестные необязательные поля версии `1` сохраняются как есть. Неизвестная версия формата при записи отклоняется.

## Редакции и удаление

- Новая редакция появляется, только когда меняется значимое содержание: текст, подпись, вложения или подтверждённое состояние. Повторный опрос без изменений редакцию не создаёт; последовательность A → B → A даёт три редакции.
- Прежние редакции сохраняются в каталоге `.history` рядом с записью и в поиск не попадают.
- Запись заменяется атомарно: новый файл готовится рядом, проверяется и только затем подменяет текущий.
- `not_found` и потеря доступа к источнику не считаются удалением. `deleted` ставится только по явному свидетельству или по команде владельца (`record_delete`, кнопка «🗑 Удалить»). Текст, редакции и вложения удалённой записи остаются в архиве.

## Проекция в OpenViking

OpenViking хранит только текущие редакции как производный индекс. URI документа равен относительному пути в архиве: `viking://resources/<путь>`. Поэтому ограничение поиска по префиксу пути (`telegram/…` или `personal/<владелец>/…`) совпадает с областями памяти.

Каждая новая редакция ставится в очередь проекции в SQLite. Работник проекции подтверждает запись только после успешного импорта; при сбое импорт повторяется позже, а архив от сбоя OpenViking не страдает. Вложения `ready` импортируются, если их формат есть в `config/openviking-formats.json`; картинки разбирает модель `vlm` из `ov.conf`. Удалённая запись снимается из индекса тем же URI. Индекс можно целиком перестроить из архива — например, после смены модели векторных представлений.

## Веб-страницы

Координатор скачивает одну страницу и превращает её в Markdown официальным программным интерфейсом Obsidian Web Clipper. Ограничения загрузки:

- только `http`/`https` на портах 80 и 443, без учётных данных в адресе;
- DNS и фактический IP проверяются до соединения и после каждого перенаправления; локальные, частные и служебные адреса блокируются;
- до 15 секунд, до 5 перенаправлений, до 10 МиБ HTML, тип `text/html` или `application/xhtml+xml`.

HTML обрабатывается только в памяти и никуда не записывается. Опасный адрес — ошибка `unsafe_url`; пустая или неполная выборка — `extraction_failed`, а не «сохранено». Повторное получение той же страницы без изменений новой редакции не создаёт.
