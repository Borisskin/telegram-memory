# API координатора

Координатор — MCP-сервер по адресу `http://coordinator:8787/mcp` (Streamable HTTP, JSON-RPC `tools/list` и `tools/call`). Наружу порт не публикуется: клиенты — боты и агент владельца внутри сетей Docker. Версия контракта — `1`; средства только добавляются, форма существующих ответов не меняется.

## Принципалы

Каждый вызов несёт заголовок `Authorization: Bearer <токен>`. По токену координатор определяет принципала; неизвестный или отсутствующий токен — `unauthorized` без данных и изменения состояния.

| Принципал | Токен | Роль |
|---|---|---|
| `system` | секрет `coordinator_mcp_token` | Агент владельца и отладка: сбор, поиск по любой области, сохранение |
| Боты | свой случайный токен у каждого; в секрете `bot_principals` хранится только его SHA-256 | `receiver` или `talker` |

Запись в `bot_principals` (её вычисляет `scripts/secrets-setup.sh` из токенов ботов и ролей в `config/secrets.json`):

```json
{ "name": "talker_shared", "role": "talker", "areas": ["shared"],
  "ownerOnly": false, "digest": false, "token_sha256": "<sha256 токена>" }
```

`areas` — доступные области (`shared`, `personal`), `ownerOnly` — отвечать только в личном чате владельца, `digest` — право на сводки. Токены Telegram-ботов координатору не передаются.

## Средства по ролям

Таблица «роль → средства» зашита в код (`src/access.ts`). Средство вне роли возвращает `forbidden` и ничего не меняет.

| Средство | Назначение | receiver | talker | system |
|---|---|:-:|:-:|:-:|
| `inbox_save` | Разобрать и сохранить входящее сообщение (с необязательным файлом `attachment`: `name`, `mime_type`, `base64`), вернуть записи и предложения кнопок | ✓ | | |
| `source_add` | Подключить источник: `full`, `summary` или `personal_chat` (последний — только receiver) | ✓ | | ✓ |
| `source_settings_set` | Включить или выключить `download_images` у источника `full` или `personal_chat` | ✓ | | ✓ |
| `collect_start` | Запустить сбор источника: `pilot`, `history`, `updates` | | | ✓ |
| `collect_status`, `collect_pause`, `collect_cancel` | Состояние, приостановка, отмена сбора | ✓ | | ✓ |
| `record_delete` | Мягко удалить личную запись владельца | ✓ | | |
| `chat_access_list`, `chat_access_set` | Доступ групп: `none`, `all_shared` или список источников | ✓ | | |
| `settings_set` | Час ежедневной сводки | ✓ | | |
| `alerts_take`, `alerts_ack` | Забрать оповещения и подтвердить их отправку | ✓ | | |
| `chat_joined` | Сообщить, что бота добавили в группу | | ✓ | |
| `knowledge_search` | Поиск в разрешённой области | | ✓ | ✓ |
| `knowledge_read` | Прочитать документ по токену чтения из поиска | | ✓ | ✓ |
| `digest`, `digest_commit` | Сводка и подтверждение её отправки | | ✓ при праве на сводки | |
| `web_save`, `personal_save`, `search` | Прямое сохранение страницы, текста и поиск | | | ✓ |

Сбор личной переписки запускается сам после `source_add` с `personal_chat`; у Приёмщика `collect_start` нет.

## Области поиска

Область выводится из префикса пути архива и равного ему URI OpenViking; модель на неё не влияет.

- **Собеседник «общий»** в группе видит только то, что разрешил владелец через `chat_access_set`. Нет записи доступа — пустой поиск. `all_shared` — все каналы и группы полного сбора. Личная область недоступна никогда.
- **Принципал «только владелец»** вне личного чата владельца получает пустую область.
- **Поиск по человеку** (`person_id`, только при доступе к личной области) возвращает его переписку и пересылки от него. Пересылки отфильтровываются после поиска, поэтому результатов может быть меньше запрошенного.
- **`system`** выбирает область явно: `all`, `all_telegram`, `source` (с `ref`) или `personal`. Неизвестный источник — ошибка, а не расширение поиска.

`knowledge_search` возвращает выдержки с `archive_id`, редакцией, датами, ссылкой и `read_token`, который действует 15 минут. Токен чтения привязан к принципалу и чату: токен из одного чата не открывает запись в другом. Если запись изменилась между поиском и чтением, `knowledge_read` вернёт актуальную версию с явной отметкой.

## Ответы и ошибки

Успех: `{ "contract_version": 1, "success": true, "data": … }`. Ошибка: `success: false` и `error` со стабильным `code`, понятным сообщением, признаком `retryable`, при ожидании — `retry_after_seconds` и `job_id`.

Основные коды: `unauthorized`, `forbidden`, `forbidden_area`, `invalid_argument`, `invalid_scope`, `unknown_source`, `unsupported_source`, `source_unavailable`, `operation_in_progress`, `pilot_not_configured`, `name_exhausted`, `rate_limited`, `timeout`, `range_too_long`, `notebook_auth`, `notebook_quota`, `upstream_unavailable`, `upstream_incompatible`, `unsafe_url`, `unsupported_content`, `unsupported_attachment` (формата нет в списке OpenViking), `extraction_failed`, `archive_corrupt`.

Ошибка поставщика никогда не превращается в пустую успешную выдачу. «Сохранено» означает запись в архив; готовность к поиску — отдельное состояние проекции.

## Сбор Telegram

- `source_add` разрешает ссылку через telegram-mcp и регистрирует источник приостановленным; повторное добавление не создаёт второй источник.
- `collect_start` без отдельного решения владельца допускает только пробу (`pilot`) по неизменяемому манифесту до 100 сообщений. У источника не больше одного действующего задания.
- Задание проходит состояния `queued` → `running` → `completed`, при временном отказе — `waiting` (включая `FLOOD_WAIT` Telegram), при постоянной ошибке — `needs_attention`, при отмене — `cancelling` → `cancelled`. После перезапуска работа продолжается с последней завершённой позиции.
- Сообщения читаются средством `list_messages` telegram-mcp. Позиция продвигается только после записи страницы в архив.
- Личные переписки опрашиваются координатором раз в 5 минут. Задание личной переписки забирает до 1000 сообщений за проход; сбой или неполный сбор виден владельцу в ответе Приёмщика и в `/status`.
